## Evidence strength

| Strength | Meaning |
|---|---|
| PROVED | A Halmos `check_*` property states the claim, within the bounds below. Where the property's oracle is solc `abi.encode`/`abi.decode` or the pinned Biconomy bytecode, it is also differential; Notes say so. |
| DIFFERENTIAL | Random inputs checked against an independent oracle: a JS/BigInt reference, viem, solc `abi.encode`/`abi.decode`, pinned Biconomy bytecode, or OpenZeppelin. |
| FUZZED | Random inputs with a property but no independent oracle (for example the NoPanic sweeps: "no Panic, only declared errors"). |
| UNIT | Example-based tests only. |
| UNBACKED | No test or property found that would fail if the claim were false. |

Each row carries the strongest class that actually covers it. When only part of the claim is covered, Notes begin with "Partial:" and say which part. A test that merely calls a function does not count as evidence for an edge-behavior claim.

## Halmos bounds

`pnpm halmos` runs `halmos --loop 70 --default-bytes-lengths 0,1,31,32,33,64,65` (`package.json:9`). A PROVED claim therefore holds for every input within those bounds and within each property's own case splits (element counts of 2 to 4, concrete head words, literal index boundaries), which the Notes state where they narrow the claim further. Halmos discards reverting paths and paths past the loop bound, and cannot decide Operations' 256/512-bit arithmetic (`AGENTS.md:259-265`), which is why most Operations rows rest on `test/math-fuzz.test.ts` instead.

Path convention: evidence is cited as `path:line`. Where a row gives a bare file name (for example `WordLambdasSymbolic.t.sol:78` or `fold.md:18`), the file lives under `contracts/tests/` or `website/src/content/docs/docs/` respectively.

## Unbacked and partially backed claims

Ordered by consequence: a claim whose failure lets a violated assertion pass or returns a wrong value comes first, then wrong or missing error detail, then gas, performance and documentation. Each item names the ledger row(s) and the kind of evidence that would close it.

### High risk

1. **W17, W28: `assertBatch` predicate entries judged like the Biconomy reference and like `assertParam`.** Equivalence with Biconomy is proved only through `assertParam` with RAW_BYTES, at most 2 constraints and 3 OR leaves; nothing relates the batch path to either oracle.

To use assertions on a chain, the four contracts must be deployed there. Check your chain below. If it is missing, you can deploy the contracts yourself.

## Add your chain

You can put assertions on any chain that meets the [requirements](#requirements). Anyone can do this, and the contracts end up at the same addresses as everywhere else.

1. Pick your chain in the table above, or add a custom RPC.
2. Connect your wallet.
3. Send one transaction for each contract. Each contract is deployed through the [deterministic-deployment proxy](https://github.com/Arachnid/deterministic-deployment-proxy) at <code>{manifest.create2Proxy}</code>, and if your chain does not have the proxy yet, you are asked to install it first.
4. Verify the contracts on your chain's explorer.

Deploy only through the proxy. Another factory, such as CreateX, produces different addresses, and the builder will not find them.

### Requirements

The chain must support the Cancun upgrade (`MCOPY` and `PUSH0`). The blob reads in Operations also need the matching block context opcodes. Before relying on a chain, check that the code is there.

## Verify the code on your chain

To check that the code at an address is the published source, open the address on your chain's block explorer and look for verified source. If an explorer shows none, verify it yourself by submitting the Solidity source with these compiler settings, which reproduce the deployed bytecode:

<ul>
  <li>Compiler: <code>{manifest.compiler.solcLongVersion}</code></li>
  <li>EVM version: <code>{manifest.compiler.evmVersion}</code></li>
  <li>Optimizer: {manifest.compiler.optimizer.enabled ? 'enabled' : 'disabled'}, {manifest.compiler.optimizer.runs} runs</li>
  <li>Metadata hash: <code>{manifest.compiler.bytecodeHash}</code></li>
  <li>Constructor arguments: none</li>
</ul>

The deployment flow above submits the source for you on explorers supported by the Etherscan multichain API.

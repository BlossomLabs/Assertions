# Actual finite stamping engine

Preparation composes every physical in-order offset load and MSTORE until the full finite offset count is consumed, then the actual helper exit. Recursive memory equals ordered writes, so overlapping windows follow last-write behavior. Constructive extent and outside-template byte-frame lemmas keep representation/resource assumptions explicit. Native and full retained public graph evidence remain open; no public coverage/gas/deployment/performance claim.

V1 is preserved. Its Outside byte-frame proof mistakenly called a whole-word frame lemma at an arbitrary byte index, and its indexed postcondition lacked an explicit prior extent result. V2 uses a checked byte-frame lemma with the same byte predicate and places the derived unchanged extent before the byte projection; the admitted memory/stamping domain is unchanged.

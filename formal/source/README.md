# Source proof restructuring

The canonical entry point is [library/README.md](library/README.md). It provides contract-separated interface indexes, package selection and a provenance checker; retained migration versions remain historical implementations.

This tree preserves a new version of source proofs alongside unchanged original source and bytecode proofs. It grants no bytecode credit. Inventory entries are candidate source inputs, not accepted results; historical copies and templates must be resolved against source-correspondence ledgers before migration.

The first representative package is Operations concat. Its original mathematical declarations and public Connection interface remain identical, including uint256 sizing, nonwrapping aligned allocation, exact overflow outcomes, and all external correspondence premises. The copied execution adapter is freshly generated by the original restricted AST gate against current production sources. Total-memory point and outside-frame lemmas now explain CopyProjection separately.

The mapping records original file hashes and complete logical interfaces. A mathematical/native pass alone does not establish source correspondence acceptance. Source generation, complete dependency/declaration coverage, audits and independent review remain required. Failed evidence directories are immutable.

Tools use `source proof-env.sh`; native verification uses two cores, isolated assertions, manual lemma induction and the original 30-second obligation limit. No old source, bytecode, production or acceptance-ledger files are edited.

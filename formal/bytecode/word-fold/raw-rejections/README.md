# Fold compiler rejection development

The generator extracts all26 ordered raw seven-head compiler rejection classes from the current Collections runtime. Range and source decoders each reject short heads, a noncanonical target, each invalid template offset/header/length/tail, each invalid element-window array offset/header/count/tail and an exit word outside0/1/2. The source decoder additionally rejects each invalid source offset/header/length/tail. The exit test uses the complete raw word, including values above255.

Each generated module retains every reached physical instruction and its actual jump destinations through `REVERT(0,0)`, from decoder PC23187 for range or22132 for bytes/words. Proof candidates preserve arbitrary lower stack prefix, arbitrary initial byte memory and the actual wrapper continuation. Ordered admissions admit loose, shared or overlapping tails wherever earlier checks accept them; they impose no canonical offset order, alignment or padding. Range count and initial accumulator keep their full uint256 domain.

`development-run.py` captures all direct owner files, the complete transitive include graph, compiler/source inputs and tool hashes before verification. It regenerates all52 owned outputs byte-for-byte and checks every declaration/native obligation and audit in all26 complete selected modules. Imported contracts remain assumed in this development run. Exhaustive rejection classification, successful decoder composition, fold body/callback/errors/output, complete included proofs, EVM fixtures, semantic faults and an independent retained checker remain required before public coverage. No gas, deployment or performance claim.

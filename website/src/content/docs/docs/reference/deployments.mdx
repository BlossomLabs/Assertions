## How the addresses stay deterministic

Deployment goes through [Arachnid's deterministic-deployment proxy](https://github.com/Arachnid/deterministic-deployment-proxy) (<code>{manifest.create2Proxy}</code>), which performs a CREATE2 with a fixed salt per contract:

```
address = keccak256(0xff ++ 0x4e59b448...956C ++ salt ++ keccak256(initCode))[12:]
```

Same proxy, same salt, same init code on every chain: same address. The salts are random 32-byte values that never change; an address moves only when the bytecode does. The four contracts call each other through interfaces at runtime addresses, never through source imports, so each one's address moves only for its own changes. The exception is `AbiCodec`, the descriptor grammar and value validator all four compile in: an edit there moves all four addresses at once.

## Deploying to a new chain

The easiest way is the [deployments page](/deployments): connect a wallet, pick the network (or add a custom RPC), and send one transaction per contract ({gasList}, measured by replaying the canonical deployment at export time). If the Arachnid proxy is missing on the chain, the page walks you through installing it permissionlessly first.

Manually, each deployment is a single transaction to the proxy with `salt ++ initCode` as calldata:

```bash
cast send 0x4e59b44847b379578588920cA78FbF26c0B4956C \
  "$(cat salt_and_initcode.hex)" --rpc-url <rpc> --private-key <key>
```

The canonical salts live in `website/scripts/export-deploy-artifact.mjs`; `pnpm sync:artifact` regenerates {manifest.contracts.map((c, i) => <span key={c.key}><code>website/{c.deploymentModule}</code>{i < manifest.contracts.length - 1 ? ', ' : ''}</span>)} (salt, init code, measured deploy gas, and predicted address for each contract), the matching ABI modules, and `website/src/lib/deployments.json` from a fresh compile. It refuses to export if the compiled bytecode no longer reproduces the expected address. Pass `--contract Operations` to regenerate only Operations and merge it into the other contracts' deployment, verification and manifest entries.

:::caution
**Do not use `hardhat ignition deploy` for the canonical deployment.** Ignition's `create2` strategy goes through the CreateX factory, which re-hashes the salt and therefore produces a *different* address than the Arachnid proxy. The Ignition module is kept only for local testing.
:::

:::note[Chain requirements]
The bytecode targets <code>{manifest.compiler.evmVersion}</code>. The deployment uses `PUSH0`, and blob-related Operations require Cancun opcode support; use Cancun-compatible chains for the full vocabulary. The exact compiler settings in `hardhat.config.ts` (solc {manifest.compiler.solcLongVersion}, optimizer {manifest.compiler.optimizer.runs} runs, evmVersion <code>{manifest.compiler.evmVersion}</code>) must not change, or the CREATE2 addresses change with the bytecode.
:::

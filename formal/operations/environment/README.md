# Operations environment source correspondence

Fifteen complete public environment bodies are gated against the pinned compiler AST, with compiler-bound selectors. The restricted translator derives observation projections from the actual primitive/member access in each body. Native connection theorems give exact block, transaction and requested-account projection, BLOCKHASH's last-256-block boundary and BLOBHASH's absent-index zero behavior.

The environment receipt must faithfully represent the world and the executing call's block/transaction. In particular, balances, code hashes and code bytes must represent the actual requested accounts; absent map entries denote the corresponding zero observation, not an arbitrary omitted account. Code-less existing accounts have the EVM empty-code hash, while nonexistent accounts have zero. Block hashes and transaction blob hashes must be the actual primitive results; cryptographic hash correctness is a premise. The primitive EVM environmental semantics, faithful AST-to-model lowering, valid decoded types, outer ABI encoding/memory projection and adequate execution resources are explicit assumptions. The same receipt may be used across calls only when those observations are stable in the relevant execution context. No claim of external-world determinism is made.

Retention requires all local native obligations, full source/dependency/compiler/tool hashes, zero audit findings, fifteen real EVM tests, and two semantic source mutations that compile/translate and fail both the native connection theorem and EVM fixture. This is conditional source evidence. Exact runtime bytecode, gas, deployment and performance remain separate.
